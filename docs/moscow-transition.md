# Московский региональный портал — контракт изменения

Принято по поручению владельца 09.11.2026. География: Москва и Московская
область, Самара и поездки вне региона не входят в публичный архив.

Владелец данных — SQLite repository. Каталог division_links получает стабильный
UUID, регион, тип и флаг архива. Имя остаётся уникальным для совместимости
со старой схемой; новые API используют UUID. Пустой URL не скрывает опубликованную
карточку. Черновик и архив скрываются целиком. DELETE архивирует запись;
PATCH archive восстанавливает как черновик. Контакты остаются только у редакции.

Миграция 9 выполняется атомарно при остановленном старом приложении, после
существующего резервного копирования deploy.sh. Старые ссылки и контакты
сохраняются. Каталог начального регионального набора — десять городов из
существующего списка; это не утверждение наличия всех окружных отделений.
Новые округа и города добавляет редактор. Неактуальные записи архивируются.
Ожидающие плановые публикации отменяются с объяснением: их старые ключи и
контрольные суммы несовместимы с изменённой схемой. История не удаляется.

Только 25 конкретных источников из прежнего общего архива снимаются с
публикации; материал московского турнира про Самару тоже исключается.
Оригиналы записываются в regional_transition_backup. Миграция 11 переводит эти
25 записей в отдельную вкладку архива медиатеки, вне активного списка.
Файлы не удаляются. Повторное открытие БД не применяет переход повторно.
Отдельный импорт использует только оставшиеся пять региональных материалов.

Публичная выборка подразделений published=1 AND archived=0; SQLite UNIQUE id
обеспечивает идентичность при переименовании. При конфликте имени API отдаёт 409. Плановая публикация использует UUID, архивные записи не являются целями.
Объём начального каталога <100: дополнительный индекс отбора не требуется;
сортировка по имени ограничена MAX 500. Сетевых операций внутри миграции нет.

Проверка: upgrade заполненной v8 и пустой БД, повтор, integrity/foreign keys,
сохранность контактов/файлов, отмена очереди, CRUD/auth/CSRF/conflict, плановое
публикация/архив, UI клавиатура/две темы/390 px, Cypress через реальный API.
Downgrade не автоматизирован: возврат старого приложения требует восстановления
предрелизной копии БД и uploads вместе. Измерение большой БД и старые concurrent
writers N/A: один экземпляр приложения, старый контейнер остановлен перед upgrade.

## Проверено локально

Vitest 5.1.0 + V8: 86 тестов проходят; исполняемые файлы src, server и
contracts включены полностью без exclusions. Команда npm run check включает
lint, tsc и coverage: frontend 96.60% lines / 94.22% branches,
backend 99.79% / 96.97%, contracts 100% / 100%.
Diff coverage harness отсутствует; отдельный процент изменённых строк не заявлен.
Cypress 16.2.1: все 14 сценариев проходят через реальные API и SQLite: создание → переименование →
публикация → архив → восстановление подразделения, медиатеки и создание
в модальном редакторе. Узкие экраны 320/390 px и обе темы проверяются
без горизонтальной прокрутки. Форматирование и тестовая компиляция проверены.
Предельное число Vitest workers ограничено двумя, timeout 30 секунд для
интеграционного теста локального Git и UI на загруженной машине; assertions,
coverage thresholds и обязательные наборы не ослаблены.
Локальная копия перед переходом: data/portal-before-moscow.sqlite (вне Git).
Production в рамках локальной реализации не изменялся.


## Доработка редакции

Миграции 10–12: таблица content_changes с ключом (kind,id), без внешнего ключа
из-за четырёх типов сущностей. Владелец — repository плановых публикаций.
Триггеры отслеживают создание и фактическое изменение черновиков; удаление,
ручное снятие с публикации, публикация и архив очищают очередь. Старые скрытые
записи не помечаются. Подразделение Люберцы добавляется без ссылки и без
перезаписи существующей записи. Версия 12 исправляет конфликт триггеров с
SQLite UPSERT через INSERT SELECT WHERE NOT EXISTS. Старые миграции сохранены.
Медиа получает archived=0/1 с CHECK: архив не может быть опубликован.
Восстановление архивного материала оставляет неопубликованный черновик.

Назначение времени атомарно проверяет отсутствие другого задания и наличие
ожидающих изменений. В момент исполнения публикуется актуальный набор всех
изменённых черновиков одной транзакцией; новые сохранения тоже включаются.
Опубликованные записи продолжают меняться сразу. Схема не откладывает их правки.
Старые задания отменяются один раз с объяснением смены правил.

Формы всех сущностей открываются в native dialog: Escape, возврат фокуса,
блокировка фона, отдельная прокрутка. Карточки подразделений занимают всю ширину;
табы архива отделены от поиска. Создание в архиве отключено. Счётчики коллекций
убраны. Герб сохранён; регион вынесен в читаемую текстовую подпись в обоих хедерах.

29 локальных HTML-макетов пересобраны командой scripts/render-design.tsx.
