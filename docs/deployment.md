# Доставка на VPS

ВМ `severniy-prod-01` (Yandex Cloud, ru-central1-d): Ubuntu 24.04,
2 vCPU × 20%, RAM 2 ГБ, SSD 20 ГБ. Адрес: `84.201.181.182`.
Временное имя: `severniy.84.201.181.182.sslip.io` (внешний DNS-сервис,
не внутренний домен Yandex Cloud). Собственный домен можно подключить позже.

## Код и данные обновляются отдельно

- Код проходит PR feature → develop → main и обязательный quality-gate.
  Создание нового неизменяемого тега MAJOR.MINOR.PATCH на коммите из main
  запускает Versioned release: проверки, сборку linux/amd64 и smoke контейнера,
  публикацию GHCR, затем reusable deploy workflow. Environment production
  сохраняет подтверждение владельца. Публикация образа не означает успешный deploy.
- Во вкладке «Обновление сайта» редактор выбирает сохранённые черновики и время
  по Москве. Сохраняются ссылки и контрольные суммы данных; Node проверяет
  очередь каждые 5 секунд и атомарно публикует только выбранные записи.
  Код, образ и Docker при этом не меняются. Перезапуск сервера не теряет очередь.
  Удаление/изменение черновика или опоздание более 10 минут завершает задание
  ошибкой без частичной публикации. Можно отменить ожидающее задание.
- Обычные кнопки публикации/снятия в редакторе продолжают действовать сразу.
  Для отложенной публикации сначала сохраните материал как черновик.

Старая очередь обновления кода больше не подключена на VPS; старые host timer
и CLI сохранены только для совместимости. Production POST /api/admin/deployments
отключён (410). Не устанавливать ops/severniy-update.timer для нового сценария.

## Сервер и доступ

`ops/bootstrap-vps.sh` — первичная установка на **новую Ubuntu 24.04** от root:
официальный Docker apt repository, Engine, Compose, SQLite, rsync, util-linux.
Docker logs ограничены 3 × 10 МБ на контейнер, systemd journal — 200 МБ.
Не применять скрипт без проверки на сервере с другими приложениями.
Node, npm и сборочные зависимости на VPS не требуются: запускается готовый образ.

Рабочий каталог `/opt/severniySait` принадлежит root. В него устанавливаются:
compose.yaml, Caddyfile, scripts/deploy.sh, scripts/check-deploy-time.sh,
scripts/backup.sh. Caddy выдаёт HTTPS; наружу выходят только 80/443,
порт приложения остаётся в Docker network. SSH доступен отдельно для управления.

GitHub Variables: DEPLOY_HOST, DEPLOY_USER, DEPLOY_PATH.
Environment production Secrets: DEPLOY_SSH_KEY, DEPLOY_KNOWN_HOSTS.
Ключ Actions отдельный, не ключ пользователя: forced command
`/usr/local/sbin/severniy-ssh-deploy` из ops/ssh-deploy.sh и authorized_keys
с опцией restrict. Пользователь severniy-deploy не входит в docker group,
может через sudo выполнять только root-owned deploy.sh. SSH принимает строго
`deploy MAJOR.MINOR.PATCH UTC`; shell, SCP и forwarding этим ключом запрещены.
Host fingerprint сверяется с журналом загрузки в консоли Yandex Cloud.

Серверный `.env` имеет права 0600 и содержит SITE_ADDRESS, RELEASE_TAG,
SESSION_SECRET и ADMIN_PASSWORD_HASH. Bcrypt hash заключён в одинарные кавычки
для сохранения `$` при Compose interpolation. Пароль и ключи не входят в Git,
Docker build context или frontend. Секрет сессии отдельный от локального сайта.
Хеш согласованного пароля хранится также в GitHub Secrets; деплой его не меняет.

Ручной workflow остаётся для повторной установки конкретного выпущенного тега
из main с явным UTC-временем. При автоматическом запуске время задаётся самим
job после подтверждения environment, непосредственно перед SSH. deploy.sh
проверяет время до/после pull, блокирует параллельные запуски и после успешного
healthcheck атомарно сохраняет RELEASE_TAG в серверном .env.

## Сохранность контента

Compose project закреплён именем severniy. База находится в volume
`severniy_portal-data`, медиа — `severniy_portal-uploads`. Они не входят в образ;
код не импортирует локальный архив при старте. Миграции расширяют существующую
БД, начальные площадки добавляются только один раз (миграция 6).
Первичный перенос локальной SQLite и uploads выполняется один раз до запуска.
Дальнейшие релизы не должны повторять этот перенос.

**Не выполнять `docker compose down -v`, не удалять volumes и не копировать
локальную БД поверх работающей.** Скрипт deploy.sh этого не делает.
Перед публикацией образа release smoke сохраняет изменения площадки и медиа
в тестовые volumes, пересоздаёт контейнер и проверяет данные через HTTP.

Перед заменой приложения scripts/backup.sh останавливает app, сохраняет SQLite
через .backup и uploads.tar.gz в `/var/backups/severniy/<UTC>`, проверяет
integrity_check и запускает прежний контейнер. Остановка нужна для согласованности
БД с файлами. При ошибке копирования EXIT trap также запускает прежний app,
а deploy прекращается. Cloud Backup настроен отдельно политикой Default daily.
Локальные копии не заменяют внешние; лимит диска следует контролировать.

Первая проверка восстановления выполняется на отдельной копии/volume, а не
поверх production. Автоматического отката кода нет: предыдущий образ допустим
только при совместимой схеме. Caddy при недоступном upstream отвечает 503 и
Retry-After:60. Один app означает короткий перерыв при обновлении кода/backup;
публикация данных контейнер не останавливает.
